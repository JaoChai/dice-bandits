# Dice Bandits M5a Cartoon Redesign Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship the chibi-cartoon look, a fixed authored map with per-game random space kinds, a follow camera and a self-explanatory board, with no rule changes beyond the new monster table.

**Architecture:** The engine swaps the chunk generator for a fixed graph (`data/map.json`) whose slot kinds are assigned per seed; coordinates become map pixels. Art is generated by the controller from the approved concepts, processed by a new `tools/cartoonize` into WebP atlases, and drawn by a 1280×720 smooth-rendered Phaser client whose board scene draws road + tiles over a painted, tiled background and follows the active token. DOM UI is re-skinned with one CSS token system; every existing `data-testid` survives.

**Tech Stack:** TypeScript 6, Phaser 4.2.1, Vite 8, Vitest 5 + happy-dom, Playwright 1.63, sharp 0.35 (tools), Cloudflare Workers, Hermes `openai-codex` image backend (controller only).

**Spec:** `docs/superpowers/specs/2026-10-02-dice-bandits-m5a-cartoon-redesign-design.md`

## Global Constraints

- Rules unchanged except the monster table (§8 of spec). Engine stays pure and deterministic: same seed → identical `GameState`.
- Room/worker protocol shape unchanged; the board stays inside `GameState`.
- Logical canvas **1280×720**, Phaser `pixelArt: false`, `roundPixels: false`, `Scale.FIT` + `CENTER_BOTH`.
- Every existing `data-testid` keeps name and meaning; existing unit + E2E tests pass (edits allowed only where a test asserts old pixel-art specifics, e.g. palette colours or 640×360 — list each edit in the PR body).
- Every new visible string in `apps/client/src/i18n/en.json` **and** `th.json`; Thai wraps, never clips.
- `?speed=0` → all motion and camera moves instant; `prefers-reduced-motion: reduce` → no shake, flash, ambient loops, camera easing (camera snaps).
- Shipped image assets (`apps/client/public/art/**`, `.webp` + `.png`) ≤ **6 000 000 bytes** total.
- Missing/failed asset → flat-shape fallback + `console.warn`, never a crash.
- Test hooks only with `VITE_TEST_HOOKS=1`; production build has no `__db`.
- No third-party CDN; fonts via `@fontsource/*`.
- Palette tokens (exact): `--c-blue #2E7FE0`, `--c-green #3BA84A`, `--c-orange #F07818`, `--c-gold #F5C51C`, `--c-red #D42B3A`, `--c-purple #6C2EBE`, `--c-grey #8E8E93`, `--c-pink #F06EA9`, `--c-cream #F5EEDC`, `--c-cocoa #5C3317`.
- Full gate for every task: `npm run typecheck && npm run lint && npm run format:check && npm test && npm run test:worker && npm run sim -- --games 200 --players 4 && npm run sim:room -- --games 200 && npm run build && npm run e2e`.
- Raw generated images are never committed; approved references live in `docs/concepts/m5/`, full PNGs in `~/Code/dice-bandits-art-staging/`.

## Review Focus

1. **Old local save (v1, grid-unit board)** on first load after deploy → save discarded, title shown, no crash. Test in Task 2.
2. **Online room created before deploy** sends a board whose space ids/coords don't match `MAP` → client shows `error.boardOutdated` and returns to title, no crash. Test in Task 6.
3. **Tapping a space while a fork choice is pending** → popup opens but the fork arrows stay clickable and the choice still dispatches. Test in Task 6.
